## 2. Búsqueda global y Explore

### API

`GET /api/search?q=&scope=all|users|posts&page=1&limit=20` requiere sesión.

- `q` se recorta, escapa como expresión regular y tiene un máximo de 80
  caracteres.
- `scope=users` busca `username` y `displayName`.
- `scope=posts` busca `content` y usa las mismas exclusiones de bloqueo,
  silencio y ocultamiento que el feed.
- `scope=all` devuelve ambos grupos con totales y paginación.
- No se exponen `passwordHash` ni `savedBy`.
- La respuesta conserva un contrato estable: `{ query, scope, users, posts,
  totals, page, limit, hasMore }`.

El cliente `usersService` centraliza la petición y `UserSearch` se monta en
`/search` y `/explore`, con filtros, carga, error y estado vacío.

## 3. Kairos Image

`POST /api/ai/images/generate` mantiene el prompt existente y admite:

```json
{
  "prompt": "...",
  "negativePrompt": "desenfoque, texto ilegible",
  "style": "cinematográfico"
}
```

`negativePrompt` tiene límite de 2000 caracteres y `style` de 80. Ambos se
almacenan en `ImageGeneration`. El servicio construye la instrucción final en
backend; ninguna clave del proveedor llega al navegador.

## 4. Kairos Video

`VideoGeneration` conserva los estados `queued`, `processing`, `completed` y
`failed`, y añade `providerJobId` y `progress`.

- `POST /api/ai/videos/generate` crea primero el documento del job.
- Si el proveedor responde con un resultado inmediato, se marca `completed`.
- Si devuelve un identificador de job, se conserva como `queued`/`processing`.
- `GET /api/ai/videos/:id/status` consulta el proveedor únicamente cuando
  existe ese identificador; de lo contrario devuelve el estado persistido.
- El frontend detiene el polling después de 30 consultas, al completar o al
  fallar. No usa temporizadores para simular una generación.

Un proveedor no configurado queda en `queued` con mensaje de configuración;
no se presenta un video falso como completado.

## 5. Editor de guion

El Centro Kairos usa el contrato existente de `Script` y `ScriptProject`:

- genera el guion con parámetros estructurados;
- permite editar título, logline, inicio, desarrollo, cierre y cierre final;
- guarda cambios mediante `PUT /api/ai/scripts/:id`;
- guarda un proyecto mediante `POST /api/ai/scripts/projects`;
- reutiliza el documento original sin duplicar el modelo.

Se añadió `DELETE /api/ai/scripts/projects/:id` para que los recursos de
proyecto también tengan ciclo de vida real.

## 6. Historial y publicación

El Centro Kairos carga los tres historiales desde MongoDB. Cada tarjeta puede:

- **Eliminar:** usa el endpoint protegido del dominio correspondiente.
- **Reutilizar:** repone los controles o la estructura del editor.
- **Publicar:** usa el servicio social existente. Las imágenes y videos se
  guardan como `Post.media`; los guiones se publican como texto. `Post.media`
  admite `image` y `video`, y Social/Detail renderizan el tipo correcto.

La autorización permanece en backend: cada consulta, actualización y borrado
filtra por `req.user.id`.

  `VIDEO_API_KEY` y del contrato de status de ese proveedor.

  no tiene `MONGODB_URI` configurado.
